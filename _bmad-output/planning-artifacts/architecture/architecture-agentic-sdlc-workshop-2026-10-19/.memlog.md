- (constraint) AGENTS.md: client-side only; React 19 + TS strict; Vite; Vitest+Testing Library; GitHub Pages static; localStorage; no new runtime deps; domain rules in src/domain free of React; no changes to workflows/vite.config/tsconfig; no any/@ts-ignore
- (version) Reality-checked against package.json/tsconfig/vite.config in repo (not training data): react/react-dom 19.3.1, typescript 7.0.2, vite 8.3.4, vitest 5.0.5, @testing-library/react 16.3.3, jsdom 30.1.3, node >=22.12 (.nvmrc used by CI). Starter already exists; no starter choice to make.
- (decision) Paradigm: functional core / imperative shell. Pure domain (src/domain) takes state+now as arguments; storage shell (src/storage) is the only localStorage toucher; React UI (src/ui, App) renders and dispatches. Prevents rules leaking into components.
- (decision) Booking is the only persisted entity (plus remembered Name). Availability, Busyness, allowance remaining, own-bookings are derived by pure functions, never stored. Prevents two sources of truth.
- (decision) Time model: date = 'YYYY-MM-DD' string in Europe/Athens; time = integer slot index 0..23 (slot 0 = 08:00); Booking = {id, roomId, date, startSlot, slotCount 1..4, name}. Single time.ts converts Instant->Athens date+minutes via Intl.DateTimeFormat timeZone Europe/Athens; no device-local Date getters anywhere; now injected as parameter. DST changes happen at 03:00-04:00, outside grid, but 'today' at midnight must use Athens.
- (decision) Window days computed by calendar arithmetic on date strings (UTC math on y/m/d), not by adding 24h to instants.
- (decision) Mutations only via domain createBooking(bookings, request, now) and cancelBooking(bookings, id, requesterName) returning Result<{bookings}, DomainError>; DomainError is a discriminated union by code with data (conflicting booking, remaining minutes); domain never throws for rule failures and never builds user-facing strings; UI maps codes to messages.
- (decision) Check order in createBooking fixed so result is deterministic: name, grid bounds/length, window, past, overlap, allowance.
- (decision) Name: normalizeName = trim + toLowerCase (toLocaleLowerCase not used; locale-independent); stored name keeps trimmed display text; every comparison (allowance, cancel, own bookings) goes through nameKey().
- (decision) Persistence: storage module loads/saves a versioned envelope {version:1, bookings} under one key 'room-booking:v1', Name under 'room-booking:name'. Commit = re-read from storage, apply domain fn, write, return new list (so two tabs on the same device cannot clobber and SM-1 holds per device). Corrupt/missing/wrong-version data -> empty list, never crash, not silently overwritten until next successful write. localStorage unavailable/quota error -> surfaced as error result, UI tells user.
- (decision) Rooms are constants in domain/rooms.ts (id small|medium|large, capacity, projector) - not persisted.
- (decision) UI: no router, no state lib; view state (selected day, room, draft) in React state; one useBookings hook wraps storage. UI may call domain predicates to disable affordances but enforcement is only at commit. Plain CSS mobile-first in styles.css.
- (decision) Past rule: slot is past when its start time < now (Athens); so in-progress slot is unavailable. Assumption on PRD FR-1.
- (decision) Deploy: static dist via existing deploy.yml; vite base from BASE_PATH so no absolute asset URLs and no client routing/pushState. Environments: local dev + Pages only; no config/secrets.
- (question) Cross-device conflicts and name-only identity: accepted PRD limitations; shared storage is a scope change needing a backend - deferred.
- (question) Measurement of SM-2 (PRD open question) - out of architecture scope.
